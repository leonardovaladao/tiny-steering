1 A language model is a function: tokens in, probabilities out

Every language model, GuppyLM included, is a neural network: a composition of simple functions that turns a list of tokens into a probability for each possible next token. By the universal approximation theorem, a large enough network can approximate any continuous function on a compact set as closely as we like; training chooses the parameters.

f = fL ∘ ⋯ ∘ f1,   fk(x) = σ(Wkx + bk)

an affine map, then a fixed nonlinearity σ; the Wk, bk are the parameters (8,726,016 in GuppyLM).

p ∈ ℝ4096,  pi ≥ 0,  Σi pi = 1

pi is the probability that vocabulary row i comes next.

simplified: a real block also has attention and LayerNorm (§3)

2 Each token becomes a vector in ℝ384

Before any computation, the text is cut into tokens, and each token is looked up as a list of 384 numbers, plus a learned vector for its position. From here on the model works only with vectors in ℝ384, and steering will later add to vectors of this same size, never to the text.

tokenized offline; live once the model loads

Try this: type “you are”, then “are you”: same ids, different positions t.

xt = E[idt] + Pos[t] ∈ ℝ384

E ∈ ℝ4096 × 384 and Pos ∈ ℝ128 × 384 are learned tables; the tokenizer uses rows 0 … 2417 (2,418 tokens), and T ≤ 128.

3 Six blocks add their outputs to one stream of width 384

GuppyLM sends these vectors through 6 transformer blocks. Each block reads a shared running sum, the residual stream, and adds its own output to it, so the width stays d = 384 throughout. Steering relies on this additive design: a vector added at one block is carried on to every later block and to the output.

4 The model writes one token per pass, then runs again

One pass through the model gives the probabilities for a single next token. The chosen token is appended to the text and the whole model runs again; a full answer is this loop repeated. Steering acts inside these passes, so it can change which token is picked at each step.

1 A concept is an arrow in the space of activations hypothesis

Everything here rests on an assumption, the linear representation hypothesis: at a given block, a concept such as food corresponds to one direction v in ℝ384, so a dot product with v reads it and moving along v changes it. It is a hypothesis, not a proven fact, and it has not been confirmed for GuppyLM.

2 Two ways to find the arrow: difference of means, or RFM

To steer we need the arrow v itself. We label prompts by concept, record their activations at one block, and compute a unit direction: difference of means joins the two class averages, while RFM fits a predictor and keeps the direction along which its gradients concentrate.

3 Steering = pushing h along the arrow, block by block

Steering adds the vector r · medℓ · vℓ to the stream at the blocks you choose; the weights stay untouched. Because blocks only add to the stream, the push travels on to the output, and every later block reacts to its shifted input. The effective dose ρ measures the total push, so different settings can be compared.

4 Where you push: the prompt, the answer, or both

Besides choosing blocks, we choose which token positions receive the vector: the prompt, the answer being written, or both. The model keeps the keys and values of earlier positions in a cache, so this choice also shapes what every later token can attend to.

5 Why r × median: the same r means the same push at every block

The vector added at each block needs a length, and a fixed length would not mean the same thing everywhere. Scaling by medℓ, the median activation length at block ℓ, turns r into a relative strength: r = 0.1 adds one tenth of a typical activation at every block.

The terms used on this page, in the order you meet them. Symbols are given next to each name.

The model

GuppyLM
A small language model (a transformer with 6 blocks and width d = 384, about 35 MB) trained to talk like a pet fish. It runs entirely in your browser, and nothing is sent to a server.
Neural network
A function built by composing simple parametrised pieces, f = fL ∘ ⋯ ∘ f1, each an affine map followed by a nonlinearity, fk(x) = σ(Wk x + bk). Training sets the parameters Wk, bk. GuppyLM has 8,726,016 parameters. Training sets them so that f gives high probability to the token that actually comes next in the training text.
Universal approximation theorem
Why this family of functions: for a non-polynomial activation σ (ReLU qualifies), every continuous function g on a compact set K ⊂ ℝn and every ε > 0, there is a network with one hidden layer of finite width N such that supx∈K |f(x) − g(x)| < ε. The theorem says such a network exists. It does not say how large N must be, nor that training will find it, and it says nothing about predicting language well.
A transformer block is more than one affine map and one σ: it also uses normalisation and attention, but it is still a composition of parametrised pieces.
Token t
The unit the model reads and writes: a word or a piece of one, with an integer id. Positions in the sequence are numbered t = 0, 1, 2, …, counting the prompt first and then the generated answer.
Vocabulary
The list of all tokens the tokenizer knows. GuppyLM's has 2,418 tokens, with ids 0 to 2417, almost all lowercase.
Embedding E
A learned lookup table E ∈ ℝ4096 × 384. Row id of E is the vector of token id. Only rows 0 to 2417 are ever used. A learned position table Pos ∈ ℝ128 × 384 is added, so the block input at position t is xt = E[idt] + Pos[t] ∈ ℝ384. It has 128 rows, so a sequence holds at most 128 tokens.
Prompt, prompt length T0
The text you type. T0 is its length in tokens after GuppyLM's chat template is applied. The prompt is limited to 56 tokens. The template puts three tokens (<|im_start|>, “user”, a newline) before your text, so your first token sits at position t = 3 of the full sequence.
Block ℓ
One of the 6 transformer layers, numbered ℓ = 0, …, 5 from input to output. Block 5 is the last one before the model picks the next token.
Activation, residual stream hℓ,t
The vector of 384 numbers that block ℓ outputs at position t. Each block adds its output to the stream it receives, so a change made at block ℓ is carried forward to every later block.
Attention
The first step of each block, where tokens exchange information. Row t takes a weighted average of (linear maps of) the rows at positions s ≤ t, never later ones. GuppyLM uses 6 heads of size 64 in parallel. Its output is added to the stream.
MLP
The second step of each block. Each position is transformed on its own: a linear map 384 → 768, ReLU, a linear map 768 → 384. Its output is added to the stream. Both steps normalise their input with a LayerNorm first.
Pre-LN block
GuppyLM's blocks are sequential and pre-LN: with x ∈ ℝ384 the block input at one position, x′ = x + Attn(LN1(x)) and then h = x′ + MLP(LN2(x′)). LayerNorm acts only on the copy each sublayer reads; the stream itself is never normalised. So a vector added to hℓ stays in the stream and reaches every later block and the output head. Each later block also reacts: its attention and MLP read a shifted input and add different outputs. So the change at block 5 is εℓvℓ plus those reactions, not εℓvℓ alone.
Unembedding, logits z
After block 5, a final LayerNorm and the matrix E (the same one as the embedding, tied weights) give one score per row of E: z = E · LN(h5,t) ∈ ℝ4096. These scores are the logits.
Softmax
Turns the logits into probabilities, pi = ezi / Σj ezj, so pi ≥ 0 and they sum to 1. The next token is drawn from p (or the largest pi is taken), appended, and the model runs again.
KV cache
During generation, the attention keys and values of every position, in every block, are stored once that position is computed. Each later forward pass computes only the newest token and reads the earlier keys and values from this cache. Attention looks only backward, so the result equals recomputing the whole sequence. A position that was steered when it was computed stays steered in the cache. The animation in the Understanding Language Models tab recomputes the whole matrix at every step for clarity; the engine's cache gives the same result.

Steering

Steering
Changing what the model writes by adding a fixed vector to its activations during generation. The weights and the prompt stay the same.
Linear representation hypothesis
The assumption behind steering along a direction: at block ℓ, a concept is read, approximately, by one linear functional h ↦ ⟨h − μ, v⟩ on ℝ384, with ‖v‖2 = 1, and moving h along v changes the concept. The method assumes it. It is not a proven fact, and the Demo has not confirmed it for GuppyLM.
Update rule
hℓ,t ← hℓ,t + 𝟙[t ∈ P] · r · medℓ · vℓ for every block ℓ in S. 𝟙[t ∈ P] is 1 when position t is in the set P and 0 otherwise. The Run the Demo tab prints this rule with your current numbers.
Concept c
A pair of opposite topics the direction is meant to separate. Positive r pushes toward the first side (label 1), negative r toward the second (label 0).
food: food and taste versus weather, seasons, TV, music, the glass, rain, outside.
valence: happy, excited, love, curious versus scared, fear, bored, tired.
env_social: water, filter, hot or cold temperature, algae versus greetings, goodbyes, friends, visitors, loneliness.
Label 1 / Label 0
Each training prompt is labelled 1 (the concept's first side, e.g. food and taste) or 0 (the second side, e.g. weather, seasons, TV). The directions are estimated from the last-token activations hℓ,T0−1 of these chat-templated prompts. On this page orange marks label 1 and blue label 0.
Concept direction vℓ
A unit vector (length 1) in the 384-dimensional activation space of block ℓ, one per block. Where it comes from is set by the vector source. Its sign is fixed so that the projection ⟨h, v⟩ correlates positively (Pearson) with the label, so +v points to label 1.
Vector source m
RFM: the top eigenvector of the AGOP of a Recursive Feature Machine trained to tell the two sides of the concept apart from block-ℓ activations. The machine alternates kernel ridge regression with a Laplace kernel and an AGOP update of the kernel's matrix M. This is the method of Towards Universal Steering (Beaglehole et al., arXiv:2502.03708), built on the Recursive Feature Machine of Radhakrishnan et al. (Science, 2024). In the real fit, the bandwidth L ∈ {1, 10, 100}, the number of iterations T ≤ 10 and row normalisation on or off were chosen on a validation split by |Pearson(⟨h, v⟩, y)|; the code's default ridge is λ = 10−3. The 2-D toy on the Understanding Steering tab uses λ = 1, a larger ridge, so that a 2-D fit does not chase noise.
DiffMeans: the mean activation on label-1 texts minus the mean on label-0 texts, scaled to length 1. A simple baseline.
Random: a direction drawn at random (fixed seed) with no relation to any concept. It is the control: a concept direction should do something a random one does not. The six uℓ are drawn independently, so their cosines are near 0 and with S = all they partly cancel in ρ.
Fisher direction
Σ̂−1(μ̂+ − μ̂−), with Σ̂ the pooled within-class covariance. It is the best linear direction when both classes are Gaussian with one shared covariance. The toy on the Understanding Steering tab draws it for reference only. In that toy, with stretched clouds, the RFM direction lines up with Fisher within the first iterations and M becomes close to rank one; this is an observation about the toy, not a theorem about RFM.
AGOP
Average Gradient Outer Product: the 384 × 384 matrix (1/n) Σi ∇f(hi) ∇f(hi)⊤ over the n training activations hi, where f is the trained predictor (the code subtracts the mean gradient first). Its top eigenvector is the input direction along which the predictor changes most, on average over the data.
Kernel ridge regression
Fits a predictor f(h) = Σi αi K(hi, h) to labels yi, with α = (K + λI)−1y, Kij = K(hi, hj) and a ridge λ > 0. In RFM the inputs are block-ℓ activations, the targets are the labels 1 and 0, and K is the Laplace kernel below.
Laplace kernel, Mahalanobis distance
KM(x, z) = exp(−‖x − z‖M / L), with bandwidth L > 0 and the Mahalanobis distance ‖x − z‖M = √((x − z)⊤M(x − z)) for a matrix M ∈ ℝ384 × 384, M ⪰ 0. With M = I it is the ordinary Laplace kernel. RFM starts from M = I and replaces M by the AGOP at each iteration, so distances count more along the directions where the predictor changes.
Activation scale medℓ
The median length ‖hℓ‖ of block-ℓ activations over the activations of all three concepts' datasets, so it does not depend on the concept. The activations are the last-token ones the directions are trained on. Norms grow along the residual stream, so a fixed step would push hard at block 0 and little at block 4. Multiplying by medℓ puts r on the same scale at every block: ‖εℓvℓ‖ / medℓ = |r|, so r = 0.1 adds a vector one tenth as long as a typical activation. The median rather than the mean is a design choice, for robustness to a few outlying norms.
Steering strength r
The number on the slider. Its sign picks the side of the concept and its size sets how hard you push. The slider is cubic, r = sign(u) · 4 · |u|³ for the handle position u ∈ [−1, 1], so small values are easy to set.
Per-block step εℓ
εℓ = r · medℓ, the length of the vector added at block ℓ. It is 0 for blocks outside S.
Blocks S
The set of blocks that receive the vector: one block (0 to 5) or all six. With one block ℓ, the added vector passes through the 5 − ℓ later blocks, which read it and react. With all, six different vectors v0, …, v5 are added and accumulate in the stream.
Positions P
The token positions that receive the vector. prompt - all tokens but last: t < T0 − 1, every prompt token except the last one. generated - last token: t ≥ T0 − 1. The name describes each step. The model writes one token per forward pass and keeps the keys and values of earlier positions in a cache. The first pass reads the whole prompt but adds the vector only at its last token, the one that predicts the first answer token. Every later pass computes only the newest token, the answer token just fed back in, and adds the vector there. So in every pass the vector goes to the last token only, and over the whole run this covers t ≥ T0 − 1. all: every position. These are mechanisms: which set pushes harder at a given r has not been measured. The first two split the sequence with no overlap. With prompt - all tokens but last, generated tokens are never steered themselves: they feel the push only through attention to the steered keys and values in the KV cache.
Effective dose ρ
ρ = ‖Σℓ∈S εℓ vℓ‖ / med5: the total added vector measured in units of a typical block-5 activation. Steering six blocks at the same r adds more than steering one, so compare settings by ρ rather than by r. Since ‖Σℓ εℓvℓ‖2 = ΣℓΣℓ′ εℓεℓ′⟨vℓ, vℓ′⟩, the numerator equals Σℓ|εℓ| when every cosine is 1 and √(Σℓ εℓ2) when the vectors are orthogonal.

Decoding

Sampling
At each step the next token is drawn at random from the model's probabilities, so the same prompt can give different answers. Recipe: divide the logits z by T, keep the k largest, renormalise with softmax, draw one token. The browser's sampler uses a different random generator from PyTorch, so sampled text does not match the Python run draw for draw; greedy text does.
Temperature T = 0.7
Divides the logits z by T before the softmax. Below 1 it makes likely tokens more likely and the text less random. It does not change which token is most likely.
Top-k k = 50
Only the 50 most likely tokens can be drawn at each step. Their probabilities are renormalised to sum to 1.
Seed
Fixes the random draws. Both answers use the same seed, so with r = 0 they are identical, and any difference between them comes from the steering term.
Paired design
The two answers share the prompt, the settings and the seed, so they use the same random draws and differ only by the steering term. At r = 0 they are identical. Once the steered text takes a different token, later draws fall on different distributions, so the two texts can no longer be compared token by token.
Greedy
Always takes the most likely token instead of sampling. The answer is then fully determined by the prompt and the settings, and matches the Python reference exactly.

Reading the answers

Unsteered and Steered
The left answer uses r = 0. The right answer uses your current settings.
Clean re-read, block 5 pt
Prompt and answer are fed again through the unsteered model, and each generated token gets the score pt = ⟨h5,t − μ5, v5⟩. Orange cells lean to label 1, blue cells to label 0, and the colour scale is shared by both answers.
Reading the steered activations instead would be circular: they contain the added vector, so the score would rise by about ε whatever the text says. With the Random source the strip still uses the RFM concept direction, so it always measures the concept.
Concept mean μ5
The mean block-5 activation over the concept's training texts. Subtracting it centres the projection.
Re-read mean
The average of pt over the generated tokens of one answer.
Judge gc
A text classifier for the concept (word and word-pair counts, TF-IDF, fed to a logistic regression). gc = 2 P(label 1) − 1 runs from −1 (clearly label 0) to +1 (clearly label 1). It reads only the text and never sees activations, so it checks the re-read from outside the model.
Judge not validated
Shown for valence. Its judge failed the pre-set accuracy check (cross-validated AUROC 0.78), so its gc is greyed out and should not be interpreted.
What is known so far
The pre-registered calibration asked whether some setting gives fluent, on-concept text that holds up on new prompts and beats a random direction. The answer was no for all 6 concept × source pairs tested (for valence the result is not interpreted, because its judge failed validation with AUROC 0.78). In the explored ranges, larger |r| tends to turn the text into word salad. The Demo's shaded band shows the coherent range for each setting.
