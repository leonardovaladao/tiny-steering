1 Um modelo de linguagem é uma função: entram tokens, saem probabilidades

Todo modelo de linguagem, como o GuppyLM, é uma rede neural: uma composição de funções simples que leva tokens a uma probabilidade para cada próximo token possível. Pelo teorema da aproximação universal, uma rede grande o bastante aproxima qualquer função contínua num compacto tão bem quanto se queira; o treino escolhe os parâmetros.

f = fL ∘ ⋯ ∘ f1,   fk(x) = σ(Wkx + bk)

um mapa afim seguido de uma não linearidade fixa σ; os Wk, bk são os parâmetros (8 726 016 no GuppyLM).

p ∈ ℝ4096,  pi ≥ 0,  Σi pi = 1

pi é a probabilidade de que a linha i do vocabulário venha a seguir.

simplificado: um block real também tem attention e LayerNorm (§3)

2 Cada token vira um vetor em ℝ384

Antes de qualquer conta, o texto é cortado em tokens, e cada token vira, por consulta a uma tabela, uma lista de 384 números, somada a um vetor aprendido para sua posição. Daí em diante o modelo só trabalha com vetores em ℝ384, e o steering vai somar vetores desse mesmo tamanho, nunca mexer no texto.

E ∈ ℝ4096 × 384 e Pos ∈ ℝ128 × 384 são tabelas aprendidas; o tokenizer usa as linhas 0 … 2417 (2 418 tokens), e T ≤ 128.

3 Seis blocks somam suas saídas a um único stream de largura 384

O GuppyLM passa esses vetores por 6 transformer blocks. Cada block lê uma soma acumulada compartilhada, o residual stream, e soma a ela a própria saída; assim a largura fica d = 384 do início ao fim. O steering depende desse desenho aditivo: um vetor somado num block segue até todos os blocks seguintes e até a saída.

4 O modelo escreve um token por passada e depois roda de novo

Uma passada pelo modelo dá as probabilidades de um único próximo token. O token escolhido é anexado ao texto e o modelo inteiro roda de novo; uma resposta completa é esse laço repetido. O steering age dentro dessas passadas, então pode mudar o token escolhido a cada passo.

2 Dois jeitos de achar a seta: diferença das médias, ou RFM

Para fazer steering precisamos da própria seta v. Rotulamos prompts por conceito, registramos suas ativações num block e calculamos uma direção unitária: a diferença das médias liga as médias das duas classes, enquanto o RFM ajusta um preditor e fica com a direção em que seus gradientes se concentram.

5 Por que r × mediana: o mesmo r dá o mesmo empurrão em todo block

O vetor somado em cada block precisa de um comprimento, e um comprimento fixo não significaria a mesma coisa em todo lugar. Escalar por medℓ, a mediana do comprimento das ativações no block ℓ, torna r uma força relativa: r = 0.1 soma um décimo de uma ativação típica em todo block.

O modelo

GuppyLM
Um modelo de linguagem pequeno (um transformer com 6 blocks e largura d = 384, cerca de 35 MB) treinado para conversar como um peixe de estimação. Ele roda inteiro no seu navegador, e nada é enviado a um servidor.
Rede neural
Uma função construída compondo peças simples com parâmetros, f = fL ∘ ⋯ ∘ f1, cada uma um mapa afim seguido de uma não linearidade, fk(x) = σ(Wk x + bk). O treino define os parâmetros Wk, bk. O GuppyLM tem 8 726 016 parâmetros. O treino os ajusta para que f dê probabilidade alta ao token que de fato vem a seguir no texto de treino.
Teorema da aproximação universal
Por que essa família de funções: para uma ativação σ não polinomial (a ReLU serve), toda função contínua g num compacto K ⊂ ℝn e todo ε > 0, existe uma rede com uma camada oculta de largura finita N tal que supx∈K |f(x) − g(x)| < ε. O teorema diz que essa rede existe. Ele não diz quão grande N precisa ser, nem que o treino vai encontrá-la, e não diz nada sobre prever bem a linguagem.
Um transformer block é mais do que um mapa afim e uma σ: ele também usa normalização e attention, mas continua sendo uma composição de peças com parâmetros.
Token t
A unidade que o modelo lê e escreve: uma palavra ou um pedaço de palavra, com um id inteiro. As posições na sequência são numeradas t = 0, 1, 2, …, contando primeiro o prompt e depois a resposta gerada.
Vocabulário
A lista de todos os tokens que o tokenizer conhece. O do GuppyLM tem 2 418 tokens, com ids de 0 a 2417, quase todos em minúsculas.
Embedding E
Uma tabela de consulta aprendida E ∈ ℝ4096 × 384. A linha id de E é o vetor do token id. Só as linhas 0 a 2417 chegam a ser usadas. Soma-se uma tabela de posições aprendida Pos ∈ ℝ128 × 384, de modo que a entrada dos blocks na posição t é xt = E[idt] + Pos[t] ∈ ℝ384. Ela tem 128 linhas, então uma sequência comporta no máximo 128 tokens.
Prompt, comprimento do prompt T0
O texto que você digita. T0 é o comprimento dele em tokens depois de aplicado o chat template do GuppyLM. O prompt é limitado a 56 tokens. O template põe três tokens (<|im_start|>, “user”, uma quebra de linha) antes do seu texto, então seu primeiro token fica na posição t = 3 da sequência completa.
Block ℓ
Uma das 6 camadas do transformer, numeradas ℓ = 0, …, 5 da entrada para a saída. O block 5 é o último antes de o modelo escolher o próximo token.
Ativação, residual stream hℓ,t
O vetor de 384 números que o block ℓ produz na posição t. Cada block soma sua saída ao stream que recebe, então uma mudança feita no block ℓ é levada adiante a todos os blocks seguintes.
Attention
O primeiro passo de cada block, em que os tokens trocam informação. A linha t faz uma média ponderada de (mapas lineares das) linhas nas posições s ≤ t, nunca das posteriores. O GuppyLM usa 6 heads de tamanho 64 em paralelo. A saída é somada ao stream.
MLP
O segundo passo de cada block. Cada posição é transformada sozinha: um mapa linear 384 → 768, ReLU, um mapa linear 768 → 384. A saída é somada ao stream. Os dois passos normalizam a entrada com uma LayerNorm antes.
Block pre-LN
Os blocks do GuppyLM são sequenciais e pre-LN: sendo x ∈ ℝ384 a entrada do block numa posição, x′ = x + Attn(LN1(x)) e depois h = x′ + MLP(LN2(x′)). A LayerNorm age só sobre a cópia que cada subcamada lê; o stream em si nunca é normalizado. Assim, um vetor somado a hℓ permanece no stream e chega a todos os blocks seguintes e à cabeça de saída. Cada block seguinte também reage: sua attention e seu MLP leem uma entrada deslocada e somam saídas diferentes. Por isso a mudança no block 5 é εℓvℓ mais essas reações, e não só εℓvℓ.
Unembedding, logits z
Depois do block 5, uma LayerNorm final e a matriz E (a mesma do embedding: pesos compartilhados, tied weights) dão um escore por linha de E: z = E · LN(h5,t) ∈ ℝ4096. Esses escores são os logits.
Softmax
Transforma os logits em probabilidades, pi = ezi / Σj ezj, de modo que pi ≥ 0 e a soma é 1. O próximo token é sorteado de p (ou se toma o maior pi), anexado, e o modelo roda de novo.
KV cache
Durante a geração, as keys e values da attention de cada posição, em cada block, são guardadas assim que essa posição é calculada. Cada passada seguinte (forward pass) calcula só o token mais novo e lê deste cache as keys e values anteriores. A attention só olha para trás, então o resultado é igual ao de recalcular a sequência inteira. Uma posição que recebeu steering quando foi calculada continua com steering no cache. A animação da aba Entendendo Modelos de Linguagem recalcula a matriz inteira a cada passo, por clareza; o cache da implementação dá o mesmo resultado.

Steering

Steering
Mudar o que o modelo escreve somando um vetor fixo às suas ativações durante a geração. Os pesos e o prompt continuam os mesmos.
Linear representation hypothesis (hipótese da representação linear)
A suposição por trás do steering ao longo de uma direção: no block ℓ, um conceito é lido, aproximadamente, por um único funcional linear h ↦ ⟨h − μ, v⟩ em ℝ384, com ‖v‖2 = 1, e mover h ao longo de v muda o conceito. O método a supõe. Ela não é um fato provado, e a Demo não a confirmou para o GuppyLM.
Regra de atualização
hℓ,t ← hℓ,t + 𝟙[t ∈ P] · r · medℓ · vℓ para todo block ℓ em S. 𝟙[t ∈ P] vale 1 quando a posição t está no conjunto P e 0 caso contrário. A aba Rode a Demo imprime essa regra com os seus números atuais.
Conceito c
Um par de temas opostos que a direção deve separar. r positivo empurra para o primeiro lado (rótulo 1); r negativo, para o segundo (rótulo 0).
food (comida): comida e sabor contra clima, estações, TV, música, o vidro do aquário, chuva, lado de fora.
valence (valência): feliz, animado, amor, curioso contra assustado, medo, entediado, cansado.
env_social (ambiente/social): água, filtro, temperatura quente ou fria, algas contra cumprimentos, despedidas, amigos, visitas, solidão.
Rótulo 1 / Rótulo 0
Cada prompt de treino recebe o rótulo 1 (o primeiro lado do conceito, por exemplo comida e sabor) ou 0 (o segundo lado, por exemplo clima, estações, TV). As direções são estimadas a partir das ativações do último token, hℓ,T0−1, desses prompts com chat template. Nesta página, laranja marca o rótulo 1 e azul o rótulo 0.
Direção do conceito vℓ
Um vetor unitário (comprimento 1) no espaço de ativações de 384 dimensões do block ℓ, um por block. De onde ele vem é definido pela fonte do vetor. Seu sinal é fixado de modo que a projeção ⟨h, v⟩ tenha correlação positiva (Pearson) com o rótulo; assim +v aponta para o rótulo 1.
Fonte do vetor m
RFM: o autovetor principal do AGOP de uma Recursive Feature Machine treinada para separar os dois lados do conceito a partir das ativações do block ℓ. A máquina alterna kernel ridge regression com um Laplace kernel e uma atualização AGOP da matriz M do kernel. Este é o método de Towards Universal Steering (Beaglehole et al., arXiv:2502.03708), construído sobre a Recursive Feature Machine de Radhakrishnan et al. (Science, 2024). No ajuste real, a largura de banda L ∈ {1, 10, 100}, o número de iterações T ≤ 10 e a normalização das linhas (ligada ou não) foram escolhidos num conjunto de validação por |Pearson(⟨h, v⟩, y)|; o ridge padrão do código é λ = 10−3. O brinquedo 2-D da aba Entendendo Steering usa λ = 1, um ridge maior, para que um ajuste em 2-D não persiga ruído.
DiffMeans: a ativação média nos textos de rótulo 1 menos a média nos textos de rótulo 0, escalada para comprimento 1. Uma linha de base simples.
Random: uma direção sorteada ao acaso (com seed fixa), sem relação com nenhum conceito. É o controle: uma direção de conceito deveria fazer algo que uma aleatória não faz. Os seis uℓ são sorteados de forma independente, então seus cossenos ficam perto de 0 e, com S = todos, eles se cancelam em parte em ρ.
Direção de Fisher
Σ̂−1(μ̂+ − μ̂−), com Σ̂ a covariância intraclasse combinada. É a melhor direção linear quando as duas classes são gaussianas com uma mesma covariância. O brinquedo da aba Entendendo Steering a desenha só como referência. Nesse brinquedo, com as nuvens alongadas, a direção do RFM se alinha com a de Fisher nas primeiras iterações e M fica perto de posto um; é uma observação sobre o brinquedo, não um teorema sobre o RFM.
AGOP
Average Gradient Outer Product (média dos produtos externos dos gradientes): a matriz 384 × 384 (1/n) Σi ∇f(hi) ∇f(hi)⊤ sobre as n ativações de treino hi, onde f é o preditor treinado (o código subtrai antes o gradiente médio). Seu autovetor principal é a direção de entrada ao longo da qual o preditor mais muda, em média sobre os dados.
Kernel ridge regression
Ajusta um preditor f(h) = Σi αi K(hi, h) aos rótulos yi, com α = (K + λI)−1y, Kij = K(hi, hj) e um ridge λ > 0. No RFM as entradas são ativações do block ℓ, os alvos são os rótulos 1 e 0, e K é o Laplace kernel abaixo.
Laplace kernel, distância de Mahalanobis
KM(x, z) = exp(−‖x − z‖M / L), com largura de banda L > 0 e a distância de Mahalanobis ‖x − z‖M = √((x − z)⊤M(x − z)) para uma matriz M ∈ ℝ384 × 384, M ⪰ 0. Com M = I, é o Laplace kernel comum. O RFM começa em M = I e troca M pelo AGOP a cada iteração, de modo que as distâncias pesam mais nas direções em que o preditor muda.
Escala das ativações medℓ
A mediana do comprimento ‖hℓ‖ das ativações do block ℓ, tomada sobre as ativações dos conjuntos de dados dos três conceitos, então ela não depende do conceito. As ativações são as do último token, as mesmas em que as direções são treinadas. As normas crescem ao longo do residual stream, então um passo fixo empurraria forte no block 0 e pouco no block 4. Multiplicar por medℓ põe r na mesma escala em todo block: ‖εℓvℓ‖ / medℓ = |r|, então r = 0.1 soma um vetor com um décimo do comprimento de uma ativação típica. Usar a mediana em vez da média é uma escolha de projeto, para ter robustez a algumas normas discrepantes.
Força do steering r
O número no controle deslizante. O sinal escolhe o lado do conceito e o tamanho define a força do empurrão. O controle é cúbico, r = sign(u) · 4 · |u|³ para a posição u ∈ [−1, 1] do cursor, para que valores pequenos sejam fáceis de ajustar.
Passo por block εℓ
εℓ = r · medℓ, o comprimento do vetor somado no block ℓ. Vale 0 para os blocks fora de S.
Blocks S
O conjunto de blocks que recebem o vetor: um block (de 0 a 5) ou todos os seis. Com um block ℓ, o vetor somado atravessa os 5 − ℓ blocks seguintes, que o leem e reagem. Com todos, seis vetores diferentes v0, …, v5 são somados e se acumulam no stream.
Posições P
As posições de token que recebem o vetor. prompt - todos os tokens menos o último: t < T0 − 1, todo token do prompt exceto o último. gerados - último token: t ≥ T0 − 1. O nome descreve cada passada. O modelo escreve um token por passada (forward pass) e guarda num cache as keys e values das posições anteriores. A primeira passada lê o prompt inteiro, mas soma o vetor só no último token dele, o que prevê o primeiro token da resposta. Cada passada seguinte calcula só o token mais novo, o token da resposta que acabou de ser realimentado, e soma o vetor ali. Então, em toda passada, o vetor vai só para o último token, e ao longo da execução inteira isso cobre t ≥ T0 − 1. todas: todas as posições. Isso são mecanismos: qual conjunto empurra mais com um dado r não foi medido. Os dois primeiros dividem a sequência sem sobreposição. Com prompt - todos os tokens menos o último, os tokens gerados nunca recebem steering diretamente: eles só sentem o empurrão pela attention às keys e values com steering no KV cache.
Dose efetiva ρ
ρ = ‖Σℓ∈S εℓ vℓ‖ / med5: o vetor somado total, medido em unidades de uma ativação típica do block 5. Fazer steering em seis blocks com o mesmo r soma mais do que em um, então compare configurações por ρ e não por r. Como ‖Σℓ εℓvℓ‖2 = ΣℓΣℓ′ εℓεℓ′⟨vℓ, vℓ′⟩, o numerador é igual a Σℓ|εℓ| quando todo cosseno vale 1, e a √(Σℓ εℓ2) quando os vetores são ortogonais.

Decodificação

Sampling
A cada passo, o próximo token é sorteado ao acaso segundo as probabilidades do modelo, então o mesmo prompt pode dar respostas diferentes. Receita: dividir os logits z por T, manter os k maiores, renormalizar com softmax, sortear um token. O sampler do navegador usa um gerador aleatório diferente do PyTorch, então o texto amostrado não coincide com o da execução em Python sorteio a sorteio; o texto greedy coincide.
Temperature T = 0.7
Divide os logits z por T antes do softmax. Abaixo de 1, torna os tokens prováveis mais prováveis e o texto menos aleatório. Ela não muda qual token é o mais provável.
Top-k k = 50
Só os 50 tokens mais prováveis podem ser sorteados a cada passo. Suas probabilidades são renormalizadas para somar 1.
Seed
Fixa os sorteios aleatórios. As duas respostas usam a mesma seed, então com r = 0 elas são idênticas, e qualquer diferença entre elas vem do termo de steering.
Paired design
As duas respostas compartilham o prompt, as configurações e a seed, então usam os mesmos sorteios e diferem só pelo termo de steering. Com r = 0 elas são idênticas. Quando o texto com steering escolhe um token diferente, os sorteios seguintes caem em distribuições diferentes, e os dois textos deixam de ser comparáveis token a token.
Greedy
Sempre pega o token mais provável, em vez de sortear. A resposta fica então totalmente determinada pelo prompt e pelas configurações, e coincide exatamente com a referência em Python.

Lendo as respostas

Sem steering e Com steering
A resposta da esquerda usa r = 0. A da direita usa as suas configurações atuais.
Releitura limpa, block 5 pt
O prompt e a resposta passam de novo pelo modelo sem steering, e cada token gerado recebe o escore pt = ⟨h5,t − μ5, v5⟩. Células laranja pendem para o rótulo 1, células azuis para o rótulo 0, e a escala de cores é a mesma nas duas respostas.
Ler as ativações com steering seria circular: elas contêm o vetor somado, então o escore subiria cerca de ε independentemente do que o texto diz. Com a fonte Random, a faixa continua usando a direção RFM do conceito, então ela sempre mede o conceito.
Média do conceito μ5
A ativação média no block 5 sobre os textos de treino do conceito. Subtraí-la centraliza a projeção.
Média da releitura
A média de pt sobre os tokens gerados de uma resposta.
Juiz gc
Um classificador de texto para o conceito (contagens de palavras e de pares de palavras, TF-IDF, alimentando uma regressão logística). gc = 2 P(rótulo 1) − 1 vai de −1 (claramente rótulo 0) a +1 (claramente rótulo 1). Ele lê só o texto e nunca vê ativações, então confere a releitura de fora do modelo.
Juiz não validado
Aparece para valence. O juiz dele falhou na verificação de acurácia definida de antemão (AUROC com validação cruzada de 0.78), então seu gc fica acinzentado e não deve ser interpretado.
O que se sabe até agora
A calibração pré-registrada perguntou se alguma configuração dá texto fluente e no conceito, que se sustenta em prompts novos e supera uma direção aleatória. A resposta foi não para todos os 6 pares conceito × fonte testados (para valence o resultado não é interpretado, porque seu juiz falhou na validação com AUROC 0.78). Nas faixas exploradas, |r| maior tende a transformar o texto numa salada de palavras. A faixa sombreada da Demo mostra a faixa coerente de cada configuração.
